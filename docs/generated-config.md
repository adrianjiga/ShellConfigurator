# Generated Config Reference

**File**: `src/generators/starship.ts`

The wizard ends by writing one `starship.toml` per selected shell. Every file is
produced by the same pure function, `generateToml(state)`, so this document is a
reference for what that output looks like and why each part is there.

## Shape of the file

`generateToml` emits, in order:

1. A header comment.
2. Three top-level keys: `format`, `add_newline`, `palette`.
3. One block per placeable module (`[<module>]`), left modules first, then right.
4. A `[character]` block, only when the character module was selected.
5. A `[fill]` block, only when at least one right-side module is configured.
6. A `[palettes.<id>]` table that every `style` in the file refers to by name.

A typical non-powerline run (default modules, plus `time` moved to the right)
produces:

```toml
# Generated by ShellConfigurator
# https://github.com/adrianjiga/ShellConfigurator

format       = "$directory$git_branch$git_status$fill$time\n$character"
add_newline  = true
palette      = "default"

[directory]
style             = "bold directory"
truncation_length = 3
truncate_to_repo  = true

[git_branch]
style  = "bold git_branch"
symbol = "on "

[git_status]
style     = "bold git_status"
ahead     = "⇡${count}"
behind    = "⇣${count}"
diverged  = "⇕⇡${ahead_count}⇣${behind_count}"
modified  = "!${count}"
staged    = "+${count}"
untracked = "?${count}"
deleted   = "-${count}"

[time]
style       = "bold time"
disabled    = false
time_format = "%H:%M"

[fill]
symbol = " "

[character]
success_symbol = "[❯](bold ok)"
error_symbol   = "[❯](bold err)"

[palettes.default]
fg              = "black"
ok              = "green"
err             = "red"
username        = "yellow"
hostname        = "green"
directory       = "blue"
git_branch      = "purple"
git_status      = "red"
nodejs          = "green"
python          = "yellow"
rust            = "red"
docker_context  = "blue"
kubernetes      = "cyan"
aws             = "yellow"
time            = "white"
battery         = "yellow"
cmd_duration    = "yellow"
jobs            = "blue"
```

## The `format` string

Modules are expanded left to right on one line, then the character is placed on a
second line:

```
$directory$git_branch$git_status$fill$time\n$character
```

- `$fill` right-aligns the right side of the prompt on the same line. It is used
  instead of `right_format` because shells pin `right_format` to the cursor line,
  which misaligns a two-line prompt (see `Technical-Design.md`).
- `\n$character` is always appended, so the prompt always ends on its own line.
- A module picked on both sides is emitted once, on the left; the right side wins
  nothing (see the `leftModules`/`rightModules` de-duplication in `generateToml`).
- The `character` module is not placeable and never appears in the format string
  directly — `buildFormatString` filters it out.

## Module blocks

Every module block starts with a `[<module>]` header. In a plain (non-powerline)
prompt each block carries a `style` key that references a **palette colour by
name**:

```toml
[directory]
style = "bold directory"
```

Starship resolves names like `directory` through the `[palettes.default]` table,
which is why the whole theme can be retuned by editing one table. Powerline
tints the text with `fg` and the segment background with the module's own colour
(the `fg:`/`bg:` spelling):

```toml
[directory]
style  = "bold fg:fg bg:directory"
format = "([ $path$read_only ](bold fg:fg bg:directory)[\ue0b0](fg:directory bg:git_branch))"
```

The `format` key is only emitted when the generated prompt is powerline. A plain
prompt leaves starship's own default format alone. The separator inside the
`format` is tinted with the *neighbouring* segment's background so adjacent
blocks interlock; the outer end of a run has no neighbour and fades into the
terminal. Blocks are wrapped in a `(…)` group that starship drops when its
variables are all empty, so a module with nothing to show collapses instead of
leaving a stray coloured block behind.

Most modules also emit module-specific settings. Ones that carry their colour in
differently-named keys do not get a `style`:

| Module          | Extra keys                                                                 |
| --------------- | -------------------------------------------------------------------------- |
| `username`      | `show_always`, `style_user`, `style_root` — no `style`                     |
| `hostname`      | `ssh_only`                                                                 |
| `directory`     | `truncation_length`, `truncate_to_repo`                                    |
| `git_branch`    | `symbol` (a Nerd Font glyph or `on `)                                      |
| `git_status`    | `ahead`, `behind`, `diverged`, `modified`, `staged`, `untracked`, `deleted` |
| `nodejs`/`python`/`rust` | `symbol`, `disabled = false`                                       |
| `docker_context` | `symbol`, `disabled = false`                                               |
| `kubernetes`    | `symbol`, `disabled = false`                                               |
| `aws`           | `symbol`, `disabled = false`                                               |
| `time`          | `disabled`, `time_format`                                                  |
| `battery`       | `disabled`, two `[[battery.display]]` tables — no `style`                  |
| `cmd_duration`  | `min_time = 0`                                                             |
| `jobs`          | `symbol`, `threshold`                                                      |

Module text symbols (`symbol`, `success_symbol`, …) branch on `hasNerdFont` so a
plain prompt degrades to readable text instead of tofu: `git_branch` uses a
space+glyph only when a Nerd Font is present, otherwise `on main`.

## The character block

The prompt character lives in `leftModules` but is not a placeable module, so it
never gets a `<section>` block or a `style` key. It is emitted on its own block:

```toml
[character]
success_symbol = "[❯](bold ok)"
error_symbol   = "[❯](bold err)"
```

The symbol (arrow, lambda, or dollar) is chosen on the style screen and carried
through state unchanged. The `ok` and `err` in the style expressions reference
the palette's `ok` and `err` colours. The character is drawn as a plain segment,
never powerline.

## The fill block

Only present when a right-side module is configured:

```toml
[fill]
symbol = " "
```

## The palette table

One `[palettes.<id>]` table closes the file. It is the single source of truth
for every colour the modules reference by name. `palette` at the top of the file
selects which table is active, so swapping the whole theme means changing one
key. Hex values pass through untouched; starship's named colours that Ink spells
differently (`purple` → `magenta`, `bright-*` → `*Bright`) are translated for the
Ink preview only, never in the generated file.
