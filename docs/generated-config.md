# Generated Config Reference

**File**: `src/generators/starship.ts`

The wizard ends by writing one `starship.toml` per selected shell. Every file is
produced by the same pure function, `generateToml(state)`, so this document is a
reference for what that output looks like and why each part is there.

> **Adopt mode** (`apply --adopt` / `--import-url`) never calls `generateToml`: the shared
> `~/.config/starship.toml` is kept in place or replaced with the fetched config, and the shells
> are wired to read it. The output below is the non-adopt per-shell default.

## Shape of the file

`generateToml` emits, in order:

1. A header comment.
2. Four top-level keys: `format`, `continuation_prompt`, `add_newline`, `palette`.
3. One block per placeable module (`[<module>]`), left modules first, then right.
4. A `[character]` block, always — `$character` always ends the format.
5. A `[fill]` block, only when at least one right-side module is configured.
6. A `[palettes.<id>]` table that every `style` in the file refers to by name.

A typical non-powerline run without a Nerd Font (default left modules, with
`time` as the only right-side module) produces:

```toml
# Generated by ShellConfigurator
# https://github.com/adrianjiga/ShellConfigurator

format              = "$directory$git_branch$git_status$fill$time\n$character"
```

## The `format` string

Modules are expanded left to right on one line, then the character is placed on a
second line:

```
$directory$git_branch$git_status$fill$time\n$character
```

- `$fill` right-aligns the right side of the prompt on the same line. It is used
  instead of `right_format` because shells pin `right_format` to the cursor line,
  which misaligns a two-line prompt (see `Technical-Design.md`).
- `\n$character` is always appended, so the prompt always ends on its own line.
- A module picked on both sides is emitted once, on the left; the right side wins
  nothing (see `placedModules` in `src/config/modules.ts`, which the preview and
  state card share).
- The `character` module is not placeable and never appears in the format string
  directly — `generateToml` drops it, along with any id that has no module
  definition, before building the format.

## Prompt-wide options

Three Style-screen choices are emitted as prompt-wide keys:

- `continuation_prompt` is the marker drawn at the start of a wrapped input
  line. The picker offers `dot` (`[∙](bright-black) `, starship's default),
  `arrow` (`[❯](bright-black) `), and `none` (`""`, no marker).
- `add_newline` inserts the blank line between the previous output and the
  prompt. It is on by default and can be turned off for a compact prompt.
- The vim-mode toggle adds `vimcmd_symbol` to the `[character]` block (see
  below).

## Module blocks

Every module block starts with a `[<module>]` header. In a plain (non-powerline)
prompt each block carries a `style` key that references a **palette colour by
name**:

```toml
[directory]
style  = "bold directory"
```

Starship resolves names like `directory` through the `[palettes.default]` table,
which is why the whole theme can be retuned by editing one table. Powerline
tints the text with `fg` and the segment background with the module's own colour
(the `fg:`/`bg:` spelling):

```toml
[directory]
style  = "bold fg:fg bg:directory"
format = "([](fg:prev_bg bg:directory)[  $path$read_only ]($style))"
```

The `format` key is emitted for every module when the generated prompt is
powerline, and as a `(\\[[…]($style)\\] )` bracket group under the Bracketed
Segments preset. Otherwise starship's own default format is left alone, with one
exception: with a Nerd Font, `directory` writes its own `format` so the folder
glyph sits in front of the path.

Powerline is only drawn when a Nerd Font is present and the preset is not a
text-only one (`drawsPowerline` in `src/config/presets.ts`); otherwise the plain
layout is generated. Each left segment after the first opens with a `\ue0b0`
arrow drawn in the previous segment's background (`fg:prev_bg`) against its own,
forming the conventional interlocking shape; right-side segments open with a
`\ue0b2` arrow in their own colour against `prev_bg`. After the last left segment
the format string adds a fade-out arrow, `[\ue0b0](fg:prev_bg)`, that ends in the
terminal background. Each separator sits inside its block's `(…)` group, which
starship drops when its variables are all empty, so a module with nothing to show
collapses together with its separator instead of leaving a stray coloured block
behind.

Most modules also emit module-specific settings. Ones that carry their colour in
differently-named keys do not get a `style`:

| Module                                                                       | Extra keys                                                                                                        |
| ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `username`                                                                   | `show_always`, `style_user`, `style_root` — no `style`                                                            |
| `hostname`                                                                   | `ssh_only`                                                                                                        |
| `directory`                                                                  | `truncation_length`, `truncate_to_repo`, `format` (Nerd Font, plain prompt), optional `[directory.substitutions]` |
| `git_branch`                                                                 | `symbol` (a Nerd Font glyph, or empty)                                                                            |
| `git_status`                                                                 | `ahead`, `behind`, `diverged`, `modified`, `staged`, `untracked`, `deleted`                                       |
| `nodejs`/`python`/`rust`                                                     | `symbol` (a Nerd Font glyph, or `node `/`py `/`rs `), `disabled = false`                                          |
| `docker_context`/`kubernetes`/`aws`                                          | `symbol`, `disabled = false`                                                                                      |
| `golang`/`java`/`dotnet`/`ruby`/`php`/`c`/`cpp`/`zig`/`lua`/`swift`/`elixir` | `symbol`, `disabled = false`                                                                                      |
| `time`                                                                       | `disabled`, `time_format`                                                                                         |
| `battery`                                                                    | `disabled`, emoji `*_symbol` keys without a Nerd Font, two `[[battery.display]]` tables — no `style`              |

| `git_commit`                                                                 | none                                                                                                              |

Module text symbols (`symbol`, `success_symbol`, …) branch on `hasNerdFont` so a
plain prompt degrades to readable text instead of tofu: `git_branch` uses the
`` branch glyph when a Nerd Font is present, otherwise an empty symbol,
so starship's default format still reads `on main`. The No Nerd Font and Plain
Text presets are text-only and get the text symbols even with a Nerd Font.

### Directory tuning

`truncation_length` is the number of parent folders the directory module shows;
`0` disables truncation and prints the full path. The Style screen's depth picker
offers 0–5 and defaults to starship's own 3.

When the user adds substitutions, the generator appends a
`[directory.substitutions]` table. Keys and values are TOML-escaped, so a folder
name containing a quote or backslash still parses:

```toml
[directory]
style  = "bold directory"
truncation_length = 1
truncate_to_repo  = true

[directory.substitutions]
"projects" = "code"
```

The table is omitted entirely when there are no substitutions, keeping the
common case short.

## The character block

The prompt character lives in `leftModules` but is not a placeable module, so it
never gets a `<section>` block or a `style` key. It is emitted on its own block:

```toml
[character]
success_symbol = '[❯](bold ok)'
error_symbol   = '[❯](bold err)'
vimcmd_symbol  = '[❮](bold ok)'   # only when vim mode is enabled
```

The symbol (arrow, lambda, or dollar) is chosen on the style screen and carried
through state unchanged. The `ok` and `err` in the style expressions reference
the palette's `ok` and `err` colours. The character is drawn as a plain segment,
never powerline. Characters that starship's format syntax treats specially
(`$`, `\`, `[`, `]`, `(`, `)`) are backslash-escaped, and the expressions are
single-quoted TOML literals (via `tomlLiteral`, not `tomlBasic`), so an escape
like `\$` for the dollar symbol survives TOML parsing unmangled.

When vim mode is enabled, `vimcmd_symbol` marks normal mode: the arrow turns
around to `❮`, while lambda and dollar keep their glyph, drawn `bold inverted ok`. It is only honoured by cmd, fish, and zsh; other shells keep the normal
character.

## The fill block

Only present when a right-side module is configured:

```toml
[fill]
symbol = " "
```

## The palette table

One `[palettes.<id>]` table closes the file. It is the single source of truth
for every colour the modules reference by name. `palette` at the top of the file
selects which table is active, so swapping the whole theme means changing one
key. Hex values pass through untouched; starship's named colours that Ink spells
differently (`purple` → `magenta`, `bright-*` → `*Bright`) are translated for the
Ink preview only, never in the generated file.
